# WO-30 / 05-MIGRATION.md C6 — a real capture of the proxy's request log.
#
# PROVENANCE. Every line below was read out of `docker logs` on the web
# container of a seeded local stack (web/e2e/support/compose.e2e.yml) while
# the chromium e2e suite drove it. None of them was written by hand; the
# only editing was selection, so that each distinct shape appears once or
# twice instead of the fifty-odd times the run produced. The three
# `outcome` lines came from the same image started against a deliberately
# broken `API_INTERNAL_BASE`, because a healthy stack cannot produce them.
#
# WHAT TO CHECK WHEN READING IT. C6 names five fields and three
# prohibitions. The fields are `method`, `path`, `status`, `duration_ms`,
# `bytes`. The prohibitions are the interesting part, and they are visible
# here rather than merely asserted:
#
#   * No API key. `ARXIV_API_KEY` is injected as `X-API-Key` on the upstream
#     hop and no header of any kind is logged.
#   * No body. The two `/research/{id}/export` lines below differ only in
#     `bytes` — 649 and 37224 — because one is a Markdown export and the
#     other a .docx. The report text itself appears nowhere. The same holds
#     for the two `/research/{id}/stream` lines: 13 bytes is a stream that
#     carried one keepalive before the browser navigated away, 396 bytes one
#     that replayed a run's frames. The frames are not in the log.
#   * No raw id, and no query string. Both export requests carried
#     `?format=`, and every `{id}` below was a real seeded identifier
#     (`baseline-succeeded`, `baseline-populated`, …). A segment is printed
#     only when it is a literal in web/contract/openapi.json.
#
# `#` lines are comments; everything else is one JSON object per line.
# web/tests/proxyLogging.test.ts parses this file and re-checks the
# prohibitions against it, so the sample is gated rather than decorative.
