## Evidence index

- `lighthouse/*.json`: six successful state/form-factor audits plus the expected failed Lighthouse navigation audit for the framework 404.
- `screenshots/*`: Lighthouse thumbnails and useful-resolution Playwright captures for the reachable route/state matrix.
- `axe/*.json`: standalone axe-core results for twelve routes/states, including both not-found paths, active/terminal job states, backend failure, and dark mode.
- `fixtures/seed-local-baseline.sh`: idempotent local-only Postgres/Redis fixture; it does not call `POST /research` or a model.
- `fixtures/capture-baseline.spec.ts`: deterministic Playwright screenshots, including an interrupted 200 SSE connection for reconnect evidence.
- `fixtures/axe-baseline.spec.ts`: deterministic standalone axe report exporter.
- [`npm-audit.json`](npm-audit.json): exact registry-backed `npm audit --json` output.

The application has two user-facing route templates, `/` and `/c/[id]`. Five meaningful product states were used for Lighthouse instead of inventing URLs: landing, empty conversation, populated report, actual plan review, and not-found/recovery. Playwright and axe cover the broader reachable state matrix.

Confirmed cross-state problems:

- The shell has no `<main>` in every audited product state.
- Large areas of content are not contained by a landmark (`region`).
- Event-log semantics produce `aria-allowed-role`/`listitem` failures in plan/failure/cancellation states.
- Several muted status/error combinations fail color contrast.
- The inline conversation-not-found state has no level-one page heading.
- Automation cannot establish keyboard order, focus restoration, announcement quality, reflow usability, or screen-reader comprehension; those remain Phase 6 manual checks.

## Other confirmed findings

- `/favicon.ico` returns 404 and lowers Lighthouse Best Practices.
- The conversation route failed the measured back/forward-cache audit.
- Mobile snapshots show the permanent 256 px sidebar leaving roughly 100 px of usable work surface.
- The failed-partial fixture proves `JobDetail.result` can coexist with failure while `ReportView` returns early and hides it.
- The built-in Next 404 is visible and axe-audited even though Lighthouse correctly treats its HTTP 404 as a page-load failure.

## Test data and safety

The baseline uses a disposable local Docker Compose stack and the deliberately invalid value `ANTHROPIC_API_KEY=local-preview-disabled`. No Anthropic/model request can succeed, and neither fixture spec calls `POST /research`.

- `seed-local-baseline.sh` upserts only `baseline-populated`, `baseline-empty`, and `job:baseline-*` records.
- Non-terminal synthetic jobs receive a local Redis lease so the production redriver does not reclaim them during capture.
- `baseline-expired` intentionally has no Redis row.
- Browser error/reconnect states are created through Playwright route interception, not live service failures.
- The stack is stopped without `-v`; named volumes are not deleted.
- The in-app Browser plugin had no connected runtime (`agent.browsers.list()` returned `[]`). Repository-owned Playwright plus local Chrome and Lighthouse supplied the browser evidence.

## Reproduce safely

Do not submit the real query form while using a valid API key. Plan generation begins a potentially billable, non-idempotent research run before the user reaches HITL review.

```bash
# Static quality, dependency evidence, and production artifact
cd web
npm ci
npm run typecheck
npm run lint
npm run test
npm run build
npm audit --json

# Local stack on explicit loopback ports, with an unusable model key
cd ..
ANTHROPIC_API_KEY=local-preview-disabled \
APP_BIND_ADDRESS=127.0.0.1 APP_PORT=18000 \
WEB_BIND_ADDRESS=127.0.0.1 WEB_PORT=13000 \
docker compose up -d

# Deterministic local-only state
docs/revamp/baseline/fixtures/seed-local-baseline.sh

# Temporary test tools: no package.json or lockfile mutation
npm install --prefix /tmp/arxiv-gate1-playwright --no-save \
  @playwright/test@1.62.1 axe-core@4.13.0

NODE_PATH=/tmp/arxiv-gate1-playwright/node_modules \
BASELINE_BASE_URL=http://127.0.0.1:13000 \
/tmp/arxiv-gate1-playwright/node_modules/.bin/playwright test \
  docs/revamp/baseline/fixtures/capture-baseline.spec.ts \
  --workers=1 --reporter=line --output=/tmp/arxiv-gate1-playwright-results

NODE_PATH=/tmp/arxiv-gate1-playwright/node_modules \
AXE_SOURCE=/tmp/arxiv-gate1-playwright/node_modules/axe-core/axe.min.js \
BASELINE_BASE_URL=http://127.0.0.1:13000 \
/tmp/arxiv-gate1-playwright/node_modules/.bin/playwright test \
  docs/revamp/baseline/fixtures/axe-baseline.spec.ts \
  --workers=1 --reporter=line --output=/tmp/arxiv-gate1-axe-results

# Example Lighthouse state
npx --yes lighthouse@13.4.1 \
  'http://127.0.0.1:13000/c/baseline-populated?job=baseline-plan-review' \
  --only-categories=performance,accessibility,best-practices \
  --output=json --output-path=/tmp/arxiv-plan-review.json \
  --chrome-flags='--headless --no-sandbox --disable-gpu'

# Graceful stop; preserve volumes
ANTHROPIC_API_KEY=local-preview-disabled \
APP_PORT=18000 WEB_PORT=13000 docker compose down
```

Verified results on 2026-08-28:

- fixture seed: exit 0;
- Playwright state matrix: 1 passed in 13.4 s;
- Playwright axe exporter: 1 passed in 5.3 s;
- `npm audit --json`: exit 0, zero vulnerabilities across 669 dependencies;
- all retained Lighthouse and axe JSON files parse successfully.

Phase 4 should evolve these discovery fixtures into the permanent application E2E/stub-server harness; the current scripts are deliberately scoped to local Gate 1 evidence.
