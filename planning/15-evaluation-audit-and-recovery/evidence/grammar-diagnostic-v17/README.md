## Confirmed evidence and hypotheses

The retained v15r2 Learn request's 7,531-byte schema was accepted by the provider;
its complete output then failed local coverage validation (repeated p3). That is
evidence of remote grammar acceptance, not accepted research content. The rejected
v16r2 Learn schema is 10,565 bytes and received the complete HTTP 400 grammar-size
response. Both requests used Sonnet 5.5, medium effort and 8,000 output tokens.

v16r2 replaced variable claim rows with eight required claim slots, including
canonical unused records, and replaced grouped coverage rows with required
per-part objects. The latter solves exactly-once part identity, but its original
status-specific branches and reference expansion add structure. The rejected
request passed the documented union/optional counters. Shared references reduce
source duplication but do not establish how the proprietary compiler expands or
optimizes them.

Hypotheses to test: unused slot expansion and repeated status branches contribute
to compilation cost; removing them may help. Neither smaller bytes, fewer unions,
SDK transformation nor MockTransport can establish remote compilation. The
[official structured-output documentation](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)
also describes interacting dimensions of complexity.

## Encoding choice

Prefer `workspace-assistance-compact-wire-v17`, subject to the diagnostic.
Emit only actual claims as a bounded array. Assign c1, c2, etc. server-side in
emission order. Claims cannot supply their own IDs or a reverse request mapping.
Coverage is still exactly one required named object per sealed part. Each object
contains status, a lossless gap-reasons collection, answer references and context
references. Full abstention has its own claim-free shape; comparison-only notes
cannot answer the comparison.

Keep the richer typed representation behind normalization. Source identity,
selected handles, material hash, parser, version, scope and Unicode offsets are
resolved from the immutable request and verified. Positional IDs are local to
this response; they never rename archived claims.

The wire enforces required part keys, closed records, enums, reference vocabulary
and claim-free full abstention. Local validation remains responsible for status/
gap compatibility, existing references, duplicate references, answer/context
overlap, orphan claims, comparison bases, selected evidence and whole-claim
support. These relationships are not claimed to be enforced by the flattened wire.
Neutral question intents cannot carry premise claims; attributed question intents
must reference scored claims. Strict JSON rejects duplicate keys and nonfinite
numbers before either validator.

The first reduction changes only fixed claim slots to an active-claim array.
The preferred reduction additionally flattens status and question branches.
The root full-abstention/normal distinction remains structural. Learn supports
eight claims and Research twelve; the maximum offline configuration has eight
requested parts. No scoring thresholds, evidence or historical results change.
