## Response/evidence repair

`workspace-qualification-adapter-v4-handles` sends Sonnet5.5 a sealed table of
short evidence handles. Each handle identifies a deterministic slice of at
most240 Unicode code points inside an explicitly selected retained span.
The model returns only handle IDs, short factual claims, bounded optional
question/proposal/limitation text, or an explicit abstention. Summaries have at
most2 factual claims and studies3. Output token caps remain1200/2400; compact
payload bounds are1800/2800 UTF8 bytes. These byte bounds are not token counts.

The server derives work/version/material/hash/parser/page/quote/offset fields
from the sealed handle map. It never searches for ambiguous quotations or
trusts model-authored provenance. The original exact identity, version, selected
span, scope and factual-check binding still apply. Metadata observations remain
metadata; abstract/excerpt evidence never becomes complete-paper evidence.
Proposals are labelled as proposals, not findings. Valid identity alone does
not establish support. Checker responses must cover every factual claim with
the exact claim-input digest. One repair and mandatory recheck remain the only
permitted additional stages, with no automatic HTTP retries.

Both local models and exact SDK-transformed schemas validate the complete
draft/check/repair/recheck fixtures. Explicit abstention has no fictitious
factual denominator and does not trigger an unnecessary checker request.
Incomplete JSON and `max_tokens` responses cannot yield accepted partial claims.
The retained real4.6 fixture reproduces1200-token truncation and all four
recoverable quote/offset mismatches. Unicode, repeated text, wrong versions,
unknown/unselected handles, changed retained material and incomplete verdicts
are regression cases. The live-scientific quality of the new contract remains
an outcome to measure, not something these tests establish.
